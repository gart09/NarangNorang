# NarangNorang 기능명세서

## 1. 서비스 개요

NarangNorang은 **Room**(스터디/동아리/모임 등 큰 단위 그룹)을 만들고, 그 안에서 **Space**(팀 단위 소그룹)로 팀원을 매칭하는 서비스이다. 유저는 초대 코드로 Room에 참여하고, 프로필 카드를 작성한 뒤 Room 내 Space에 가입 신청하거나 초대를 받아 소그룹 활동을 진행한다.

- 인증: JWT 기반 (Access Token 1시간, Refresh Token 120시간)
- 실시간 기능: Room/Space 채팅 (WebSocket STOMP)

## 2. 도메인 흐름

1. 유저가 **Room을 생성** → 생성자가 Room 오너가 되고, 초대 코드가 자동 발급됨
2. 다른 유저가 **초대 코드로 Room에 참여** (`GET /rooms/join/{roomCode}` 자체가 참여 처리)
3. Room 멤버는 **프로필 카드**를 작성 (Room 오너가 프로필 카드 커스텀 필드 형식을 관리)
4. Room 내 모든 멤버는 **Space를 생성**할 수 있음 (생성자가 Space 오너, 생성 시 프로필 카드 필수 동반)
5. 다른 멤버는 Space에 **가입 신청**하거나, Space 오너가 멤버에게 **가입 권유**를 보냄 → 상대측의 수락으로 가입 완료
6. Room/Space 단위로 **채팅** 가능

## 3. 도메인별 기능

### 3.1 회원(User)

| 기능 | 설명 |
|---|---|
| 회원가입 | 이메일/비밀번호/이름으로 계정 생성 |
| 로그인 | 이메일/비밀번호로 로그인, 액세스/리프레시 토큰 발급 |
| 토큰 재발급 | 만료된 액세스 토큰을 리프레시 토큰으로 갱신 |
| 로그아웃 | 리프레시 토큰 무효화 |
| 내 정보 조회 | 로그인한 유저 본인 정보 조회 |
| 내 정보 수정 | 이름/비밀번호 수정 (미입력 필드는 기존값 유지) |
| 회원 탈퇴 | 계정 삭제 |

### 3.2 룸(Room)

| 기능 | 설명 | 권한 |
|---|---|---|
| 룸 생성 | 룸 생성, 초대 코드 자동 발급, 오너의 프로필 카드 자동 생성 | 로그인 유저 |
| 룸 상세 조회 | 룸 정보 + 커스텀 필드 목록 조회 | 룸 멤버 |
| 초대코드로 룸 조회 | 초대 코드로 룸 조회, 본인의 참여 여부(member) 함께 반환 | 로그인 유저 |
| 룸 정보 수정 | 이름/설명/최대 인원 수정 | 룸 오너 |
| 룸 커스텀 필드 관리 | 프로필 카드 커스텀 필드 일괄 등록/수정 (기존 필드는 이름·타입·옵션 수정 불가, 삭제 후 재생성만 가능) | 룸 오너 |
| 룸 삭제 | 룸 및 하위 데이터 삭제 | 룸 오너 |

**커스텀 필드 입력 방식**: 짧은 글(TEXT), 숫자(NUMBER), 하나 선택(SINGLE_SELECT), 여러 개 선택(MULTI_SELECT) 4종.

> ⚠️ 알려진 한계: MULTI_SELECT 답변은 값 1개만 저장 가능한 구조라, 체크박스 다중 선택 저장 시 값이 덮어써질 수 있음.

### 3.3 멤버 프로필 카드(MemberProfileCard)

| 기능 | 설명 | 권한 |
|---|---|---|
| 프로필 카드 생성 | 초대 코드로 룸에 참여하며 프로필 카드 작성 (이름 + 커스텀 필드 답변) | 로그인 유저 |
| 조건 조회 | 이름/룸/커스텀필드 값으로 프로필 카드 필터링 조회 | 로그인 유저 |
| 수정 | 본인 프로필 카드의 이름/답변 수정 | 본인 |
| 삭제 | 본인 프로필 카드 삭제 | 본인 |
| 내 룸 목록 조회 | 내가 프로필 카드를 가진(참여 중인) 룸 목록 조회 | 로그인 유저 |

### 3.4 스페이스(Space)

| 기능 | 설명 | 권한 |
|---|---|---|
| 스페이스 목록 조회 | 룸 내 스페이스 목록, 태그로 필터링 가능(모두 포함 매칭) | 룸 멤버 |
| 스페이스 상세 조회 | 프로필 카드, 태그, 오너 이름 포함 상세 조회 | 룸 멤버 |
| 스페이스 생성 | 이름/최대 인원/기술스택/선호시간/커스텀필드/태그와 함께 생성, 생성자가 오너 및 첫 멤버가 됨 | 룸 멤버 |
| 스페이스 수정 | 기본 정보 + 프로필 카드 + 태그 수정 | 스페이스 오너 또는 룸 오너 |
| 스페이스 삭제 | 스페이스 및 하위 데이터(프로필카드, 태그, 멤버) 삭제 | 스페이스 오너 또는 룸 오너 |
| 룸 내 태그 목록 조회 | 룸에서 사용된 모든 태그 이름 중복 제거 조회 | 룸 멤버 |
| 스페이스 탈퇴 | 멤버 본인 탈퇴. 오너는 탈퇴 불가(먼저 위임 필요) | 스페이스 멤버 |
| 오너 위임 | 다른 멤버에게 오너 권한 위임 | 스페이스 오너 또는 룸 오너 |
| 멤버 목록 조회 | 스페이스 멤버들의 프로필 카드 목록 조회, 비가입 룸 멤버도 조회 가능 | 룸 멤버 |

### 3.5 스페이스 가입 신청/권유(InviteSpace)

| 기능 | 설명 | 권한 |
|---|---|---|
| 가입 신청 | 룸 멤버가 스페이스에 가입 신청 (스페이스 오너 수락 필요) | 룸 멤버 |
| 가입 권유 | 스페이스 오너가 룸 멤버를 초대 (대상자 수락 필요) | 스페이스 오너 |
| 스페이스 대기 목록 조회 | 특정 스페이스에 걸린 신청/권유 대기 목록 조회 | 스페이스 오너 |
| 내가 받은 요청 목록 조회 | 본인이 승인 권한자인 모든 신청/권유 대기 목록 조회 (여러 스페이스 통합) | 로그인 유저 |
| 수락 | 대기 중인 신청/권유 수락 (수락 시 스페이스 멤버로 등록, 인원수 증가) | 승인 권한자 |
| 거절 | 대기 중인 신청/권유 거절 | 승인 권한자 |

**승인 권한자 판별 규칙**
- 멤버가 신청한 경우(MemberToSpace) → 승인자는 스페이스 오너
- 오너가 권유한 경우(SpaceToMember) → 승인자는 대상 멤버

**수락 시 재검증**: 신청/권유 당시엔 룸 멤버였으나 이후 룸을 탈퇴했거나, 이미 다른 경로로 스페이스 멤버가 된 경우 수락이 거부됨.

### 3.6 채팅(Chat)

| 기능 | 설명 | 권한 |
|---|---|---|
| 메시지 전송 | 룸 또는 스페이스에 메시지 저장 후 WebSocket으로 구독자에게 브로드캐스트 | 대상에 접근 권한 있는 유저 |
| 이력 조회 | 룸/스페이스 채팅 이력을 페이지 단위(Slice)로 조회 | 대상에 접근 권한 있는 유저 |

- WebSocket 연결: `/ws` (SockJS)
- 구독 경로: `/sub/room/{roomId}`, `/sub/space/{spaceId}`
- 발신: REST `/chat/send` 호출 → 서버가 해당 구독자에게 브로드캐스트

## 4. 권한 요약

| 대상 | 권한자 |
|---|---|
| 룸 정보 수정/삭제 | 룸 오너 |
| 룸 커스텀 필드 관리 | 룸 오너 |
| 스페이스 정보 수정/삭제/오너위임 | 스페이스 오너 또는 룸 오너 |
| 스페이스 가입 신청 확인/멤버 초대 | 스페이스 오너만 |
| 프로필 카드 수정/삭제 | 본인만 |

## 5. 인증/인가

- 인증 방식: JWT (Stateless)
  - Access Token 유효기간: 1시간
  - Refresh Token 유효기간: 120시간
  - 요청 헤더: `Authorization: Bearer {accessToken}`
  - 토큰 갱신: `Refresh-Token` 헤더 또는 `POST /users/checkRefreshToken`
- JWT payload 포함 정보: 유저 ID, 유저명(한글 포함, UTF-8), 권한(roles)
- 인증 없이 접근 가능한 경로: 회원가입, 로그인, 토큰 재발급, WebSocket 핸드셰이크, 정적 리소스

## 6. 알려진 제약사항

- MULTI_SELECT 커스텀 필드 답변은 값 1개만 저장 가능 (다중 선택 결과가 마지막 값으로 덮어써질 수 있음)
- 스페이스 목록 응답(SpaceSummaryResponseDto)에는 오너 여부/가입 여부 정보가 없어, 목록 화면에서 오너 표시나 가입 여부 UI는 제공되지 않음
- 스페이스 선호 시작/종료 시간은 시각(HH:mm)만 의미가 있으나, 데이터 타입상 날짜(더미값 1970-01-01)가 포함되어 저장됨
